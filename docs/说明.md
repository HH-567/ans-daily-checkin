# 说明：解决什么问题、核心功能、怎么跑起来，以及范围与边界

这份文档按「先讲清楚它是干什么的，再讲怎么用，最后讲边界」的顺序组织。

想直接上手，看 [README](../README.md) 的「快速开始」也可以。

## 一、解决什么问题

### 1. 要解决的痛点

ANS 工作台的「算力福利街」每天有一组可领取的奖励：

| 任务 | 奖励 |
|---|---|
| 每日算力签到 | +5 积分 +1 币 |
| VibeHub 沉浸充电 60 秒 | +5 积分 +1 币 |
| 星火助威 · 点亮 Star | +5 积分 |
| 小恐龙特训 · 投喂/对话 | +3 积分 |

单账号一天要重复点 4 次；有多个账号就是 4×N 次，还要逐个登录切换。这件事本身没有难度，但：

- **容易忘**：漏一天就断签，连续天数重来
- **多账号更麻烦**：每个账号都要走一遍登录、进页面、点按钮
- **结果不可信**：页面点了会显示「✓ 已打卡领取」，但那只是前端乐观更新——服务端可能根本没记账（站点自身 bug），你以为领到了，其实没有

### 2. 这个工具解决什么

| 痛点 | 解决方式 |
|---|---|
| 每天要手动点 | 定时自动执行，人不用在场 |
| 多个账号切换麻烦 | 一次配置，全部账号串行执行，结果分开统计 |
| 容易忘、会断签 | 开机补跑 + 定时任务双保险 |
| 不知道到底领没领到 | 以**积分余额**为准记录，而不是看页面提示 |
| 忘了哪些账号失效了 | 列表直接标出「需要重新登录」 |

一句话：**把每天 30 秒的重复操作变成 0 秒，并给出一个可信的结果账本。**

### 3. 不解决什么

它不是「刷分工具」——不会绕过风控、不会多倍领取、不会伪造数据。它只是把你每天该点的那几下，换成程序替你点。

## 二、核心功能

### 1. 自动签到与日常任务

- 4 个任务可自由勾选（只想签到的可以只留 `daily_checkin`）
- 支持手动触发、定时执行、开机补跑
- **幂等**：已领过只返回 `duplicate`，重复执行不会重复加分，所有入口同时跑也安全

### 2. 多账号管理

- 三种添加方式：**账号密码 / 粘贴 Cookie / 浏览器登录**
- 密码只在内存里换一次凭证，**不落盘**
- 支持停用、启用、删除、单账号单独执行
- 账号之间失败隔离：一个失效不影响其他账号继续跑

### 3. 无人值守

- Windows 计划任务每天定时执行（默认 12:00，可在界面里改）
- 开机自启后补跑一次（6 小时内跑过则跳过）
- 执行完成弹系统通知：本次加了多少分、哪些账号失败、哪些需要重新登录

### 4. 结果可见

原生窗口（Windows 客户端）与网页控制台都能看到：

- 账号列表：积分、今日签到状态、上次执行时间
- 四个统计数字：账号数 / 总积分 / 今日已领 / 上次执行
- **积分历史曲线**：每个账号的余额变化，只有真加分才向上走
- **最近执行记录**：时间 / 账号 / 领取 / 结果
- 实时执行日志：边跑边出，不是等完才显示

### 5. 失败可诊断

结果按类型分开，不用猜：

| 情况 | 标记 |
|---|---|
| 正常领取 | 已签到 / 已领取 |
| 今天已经领过 | 今日已领过 / 无新增 |
| Cookie 失效 | 需要重新登录 |
| 站点接口报错 | 服务端拒绝（`COMPUTE_BENEFITS_FAILED`） |
| 网络问题 | 自动重试，持续失败才报错 |

命令行还有退出码：`0` 正常、`1` 错误、`2` 需要登录、`3` 部分失败、`4` 服务端拒绝。

### 6. 完全本地

- 凭证存在本机文件里，**无遥测、无上报、无云端**
- 本地服务只监听 `127.0.0.1`，不对局域网开放
- 不依赖第三方服务，不依赖浏览器常驻

## 三、怎么运行体验

### 方式 A：试用一次（约 3 分钟，不装客户端）

适合「先看看能不能用」的人。

```powershell
# 1. 装 Node.js 18+（https://nodejs.org），确认版本
node -v

# 2. 装依赖（只有浏览器登录方式需要）
npm install

# 3. 添加一个账号（三选一）
node login-password.mjs    # 邮箱 + 密码，密码输入不回显
node import-cookie.mjs     # 粘贴浏览器里复制的 Cookie
node grab-cookie.mjs       # 打开浏览器手动登录，自动抓取

# 4. 先空跑一次，不实际请求，确认账号和任务列表对不对
node checkin.mjs --dry-run

# 5. 真正执行
node checkin.mjs
```

跑完看两点：控制台输出的「积分：X → Y」，以及 `logs/<日期>.log` 里的完整过程。

> 建议第一次只勾 `daily_checkin`，确认积分真的涨了，再打开其他任务。

### 方式 B：日常使用（桌面客户端）

适合「配好之后不想再管」的人。

```powershell
# 1. 构建 exe（需要 Node 已装好）
.\build-exe.ps1

# 2. 双击运行
.\ANS签到.exe
```

打开后会看到一个原生窗口：

1. 点「添加账号」，选一种方式把账号加进来
2. 点「全部执行」，或直接等定时任务
3. 关掉窗口只是收进托盘，程序继续在后台跑

托盘右键可以：打开控制台 / 立即签到 / 打开数据文件夹 / **开机自启**。

想让它在固定时间自动跑，注册计划任务：

```powershell
.\register-task.ps1                    # 默认每天 12:00
.\register-task.ps1 -Times 09:00,21:00 # 或自定义多个时间
```

也可以在窗口底部「执行时间」里直接改，保存后会同步更新 Windows 计划任务。

### 方式 C：网页控制台

装好之后，应用运行期间用浏览器打开：

```
http://127.0.0.1:8787/
```

功能与原生窗口一致，另外多一个「导出历史」。适合想用浏览器调试、或想在大屏上看曲线的时候。

### 三种方式怎么选

| 你的情况 | 建议 |
|---|---|
| 只想试试能不能用 | 方式 A，命令行跑一次 |
| 想每天自动跑、不折腾 | 方式 B + 注册计划任务 |
| 喜欢网页界面 / 要导出数据 | 方式 B 或 C，浏览器打开控制台 |

## 四、具体做法

### 1. 一句话

不模拟点击，直接调用站点前端自己在用的那个业务接口；登录态复用站点自己的登录接口换取 Cookie，密码不落盘。

### 2. 为什么不是浏览器自动化

逆向站点前端后确认了一件事：**页面上的「签到」按钮本身不产生任何积分**。

```
用户点击签到
   ↓
前端只改浏览器 localStorage（键名 ans_quest_arcade_v3）
   ↓
真正记账的那一步是：
   POST /api/compute-benefits/arcade
   {"kind":"quest","questId":"daily_checkin"}
   ↓
服务端返回 {grantedPoints, balanceAfter, duplicate, operationKey}
```

积分、连续签到天数、爪爪币全部由服务端结算，`localStorage` 只是界面缓存。所以只要带上有效登录态直接调这个接口，**效果和手动点一次完全一致**，不需要开浏览器。

| | 浏览器自动化（Playwright / Selenium） | 本方案（直接调接口） |
|---|---|---|
| 单次耗时 | 10～20 秒 | 1～2 秒 |
| 依赖 | 常驻 Chromium + 驱动 | 只要 Node.js |
| 无人值守稳定性 | 受弹窗、版本更新、配置锁影响 | 无 GUI 依赖 |
| 出错排查 | 看截图猜 | 结构化日志 + 退出码 |

### 3. 三个层次

**认证层**（`lib/ans-auth.mjs`）

1. `GET /api/auth/csrf` 拿 csrfToken
2. `POST /api/auth/callback/credentials`（email / password / callbackUrl / json）
3. 从响应头取 `__Secure-authjs.session-token`

支持三种凭证来源：

- 密码 → 现场换 Cookie，**密码只在内存里用一次，不写盘**
- 粘贴 Cookie / cURL → 直接校验有效性
- 浏览器登录 → 独立配置目录里人工登录，检测到成功自动抓取

**执行层**（`checkin.mjs`）

逐个账号串行执行，每个账号按 `config.json` 里的 `quests` 依次调用接口。

**调度与界面层**

- Windows 计划任务（默认每天 12:00）
- 开机自启后补跑一次（6 小时内已跑过则跳过）
- 原生窗口 / 网页控制台手动触发

三条入口调的是**同一份** `checkin.mjs`，逻辑不会分叉。

### 4. 数据与存储

全部在本机，没有数据库、没有云端：

| 路径 | 内容 | 敏感 |
|---|---|---|
| `accounts/<id>.json` | 账号 Cookie、昵称、启用状态 | **是，等同登录凭证** |
| `config.json` | 任务开关、执行时间、重试参数 | 否 |
| `logs/<日期>.log` | 人类可读的执行日志 | 含邮箱 |
| `logs/runs.jsonl` | 结构化执行记录（每行一条 JSON） | 含邮箱 |
| `desktop-ui.json` | 界面折叠状态等偏好 | 否 |

`accounts/` 与 `logs/` 已在 `.gitignore` 里，**不要提交、不要分享**。

### 5. 运行环境

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11（依赖系统自带 .NET Framework 编译的 exe） |
| Node.js | 18 及以上（开发与测试基于 Node 24） |
| 管理员权限 | **不需要** |
| 前端依赖 | 仅 `playwright-core`，且只在「添加账号→浏览器登录」时用到 |
| 网络 | 能访问 `ans.cauai.fun` |

桌面客户端是约 400 KB 的原生 exe，不打包 Electron / Tauri，只负责：拉起本地服务、托盘常驻、弹出结果通知。

## 五、适用人群

### 适合

- **每天会打开这台电脑的 ANS 用户**：想省掉每天点几下，又不想依赖手机
- **有多个账号的人**：主号 + 小号一起维护，逐个执行、结果分开统计
- **接受"凭证存在本机"的人**：明白 `accounts/` 里的文件等同于登录状态
- **能按步骤配一次的人**：装 Node、双击 exe、添加账号，之后基本不用管

### 不适合

- **想多开刷分 / 薅羊毛的**：本工具不规避风控，多账号高频请求反而更容易被判定异常
- **想要云端托管、关机也跑的**：这是本地程序，电脑关了就停
- **期望"装上就完全忘记"的**：Cookie 会过期，偶尔需要重新登录一次
- **想绕过验证码、风控、活动规则的**：这些都不在能力范围内

### 用之前请自问三个问题

1. 我是否清楚这个账号的登录凭证会以文件形式存在本机？
2. 我是否能接受"自动化领取日常任务"可能不符合站点活动规则？
3. 站点改版导致工具失效时，我是否愿意等更新或自己改？

三个都「是」再往下走。

## 六、服务边界

### 1. 能做什么

- 在你自己的账号上，代替「点一下领取」这个动作
- 按天自动执行、失败重试、记录结果
- 多账号批量处理，结果分开统计
- 本地查看积分历史、执行记录、日志

### 2. 不做什么

| 不做 | 原因 |
|---|---|
| 绕过登录 / 验证码 / 二次验证 | 超出范围，也不该做 |
| 规避风控、伪装请求频率、伪造设备指纹 | 同上 |
| 伪造积分、修改服务端数据、篡改前端缓存 | 只调站点自身接口，不造数据 |
| 批量注册账号 | 与工具目的无关 |
| 代挂、账号共享、云端托管 | 凭证不出本机 |
| 保证 100% 领取成功 | 见「效果边界」 |

### 3. 效果边界

以下情况**会领不到**，属于正常现象而非工具故障：

- **站点接口本身报错**：`daily_checkin` 目前就可能返回 500，真实点击同样失败
- **活动规则调整**：奖励数量、任务 ID、触发条件变化
- **每日重置时间变化**：工具按你设置的时间跑，跑早了会被判「今日已领过」
- **账号侧风控**：站点判定异常时可能拒绝发放
- **Cookie 过期**：需要重新登录

工具能做的是**把失败原因说清楚**，而不是保证结果。

### 4. 数据边界

- 所有凭证、日志只存在本机，**无遥测、无上报、无统计**
- 本地服务只监听 `127.0.0.1`（同时监听 `[::1]` 便于 `localhost` 访问），**不对局域网开放**
- 不做任何形式的账号数据同步

### 5. 维护边界

- 站点改版、接口签名变化会导致失效，需要更新代码才能恢复
- 没有服务等级承诺（SLA），不保证长期可用
- 不提供「保证不被封号」之类的承诺，风险自担

### 6. 合规与风险

- 本工具走的是站点自己前端在用的同一个接口，不伪造数据、不绕过权限
- 但「自动领取日常任务」类操作（点亮 Star、投喂小恐龙等互动任务）本质上是把本该人工完成的交互自动化了，**可能不符合站点活动规则**
- 想降低风险，把 `config.json` 里的 `quests` 改成只剩 `daily_checkin`
- 账号出问题的后果由使用者承担

### 7. 已知限制

| 限制 | 说明 |
|---|---|
| 需要 Node.js | 没有做成免安装绿色包 |
| 只支持 Windows | 计划任务、exe、托盘都是 Windows 的实现 |
| 单机运行 | 换电脑要重新添加账号 |
| 界面为原生 WinForms | 视觉上限低于网页，但完全不依赖浏览器 |
| 导出功能仅在网页控制台 | 原生窗口暂未提供 |
| 依赖站点接口稳定 | 接口一旦变更就会失效 |

## 七、常见疑问

**Q：会不会被判定为作弊？**
A：工具调用的是站点自己的接口，行为和手动点击一致；但"自动化"这件事本身是否被允许，取决于站点规则，工具无法替你保证。

**Q：为什么签到成功了但积分没涨？**
A：先看积分余额有没有变化。`COMPUTE_BENEFITS_FAILED` 是站点 bug，前端会错误地显示"已打卡"，但服务端并没有记账。

**Q：Cookie 会存多久？**
A：跟随站点会话有效期。过期后账号会标红「需要重新登录」，重新添加即可。

**Q：能不能不用 Node.js？**
A：目前不行。真正的业务逻辑在 Node 脚本里，exe 只是外壳。

**Q：多账号会互相影响吗？**
A：不会。逐个串行执行，失败隔离。

**Q：跑一次要多久？**
A：单账号 1～2 秒，多账号依次累加。四个任务全开大约每个账号 3～5 秒。
